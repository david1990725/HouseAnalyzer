# 住得明白｜AI Rental Property Analyzer

> 零依賴、Local-first、以客觀事實挑戰主觀直覺的 AI 租屋比較與前瞻決策分析系統。

可安裝的繁體中文 Progressive Web App (PWA)，以「客觀事實推演」與「家庭生活策略」為核心，重塑台灣租屋看房決策流程。使用者自帶 API Key (BYOK)，主觀筆記純本地保存，橫向比較時 AI 會讀取主觀筆記以識別偏誤並反向檢驗，而非迎合偏好。

---

## 核心設計理念

| 理念 | 說明 |
| :--- | :--- |
| **以客觀事實挑戰主觀直覺** | 直覺評分、心動亮點、家庭隨筆等主觀資料**純本地 `localStorage` 保存**。單物件分析時 AI 嚴格只接收客觀資料；橫向比較時 AI 會讀取主觀筆記，但目的是**用客觀事實與查核數據反向檢驗**——更正盲點、戳破過度樂觀、平反不必要的焦慮，而非迎合偏好。 |
| **Local-First 架構** | 所有物件資料、看房筆記、分析報告皆儲存於瀏覽器本地。無資料庫、無平台綁定，安裝 PWA 後可離線瀏覽介面與編輯筆記。 |
| **BYOK 金鑰安全** | 使用者自行輸入 API Key，Key 僅存於 `sessionStorage`（關閉瀏覽器即消失）。伺服器端不保存金鑰，每次請求僅透傳至對應 AI 提供商。 |
| **零依賴輕量前端** | 純 HTML + CSS + Vanilla JS，無任何框架依賴。字型使用 Noto Sans TC + DM Mono (Google Fonts)。 |

## 功能特色

### 物件管理

- 新增、編輯、刪除租屋物件（最多管理多間）
- 支援 Markdown (`.md`) 格式一鍵匯入與匯出，資料永遠可攜
- 內建去識別化示範資料（三間範例物件 + 示範家庭），可一鍵載入體驗完整流程

### 家庭資料設定

- 家庭成員年齡與通勤地點
- 月收入組成與租屋核心需求清單
- 作為 AI 比較分析的全域脈絡參考

### AI 單物件分析 (`/api/analyze`)

> **此端點嚴格只接收客觀資料**，請求中若包含 `subjective` 欄位將被拒絕。

- 總評分與推薦判斷
- 交通、學區、空間／屋況、周邊環境四大面向各自評分與評語
- 現有優勢 (Strengths) 與問題 (Weaknesses)
- 具可信程度標示的未來機會 (Opportunities) 與風險 (Threats)：`confirmed` / `likely` / `possible` / `speculative`
- 最大交換條件、適合與不適合的生活情境、待查事項

### AI 多物件橫向比較 (`/api/compare`)

> **此端點同時接收客觀規格與主觀筆記**。AI 的角色是「決策教練」——用客觀事實與即時查核數據反向檢驗使用者的主觀直覺，一針見血更正盲點與過度樂觀，而非迎合偏好產出報告。

支援 2–3 間物件同時比較，產出 **十一大結構化決策模組**：

| 模組 | 內容 |
| :--- | :--- |
| ① 先講結論 | 客觀量化總分排名與核心定位判斷 |
| ② 各物件深入面向分析 | 交通、學區、空間屋況、周邊氛圍 4 大面向獨立推演與警示 |
| ③ 租金真正的差異 | 原始月成本 vs 租補後實質支出對比 |
| ④ 租約條款與維修風險 | 維修責任歸屬、已知問題、隱性維修成本試算 |
| ⑤ 生活策略框架 | 將物件重新定位為具體的生活方式選擇 |
| ⑥ 真正的問題 | 挖掘使用者真正卡關的核心決策困境 |
| ⑦ 核心平衡結論 | 各物件「得到什麼 vs 承擔什麼」 |
| ⑧ 優先順序情境排名 | 依預算 / 學區 / 通勤等優先度動態調整排名 |
| ⑨ 條件式排名反轉 | 哪些關鍵事實確認後會導致排名翻轉 |
| ⑩ 實地查驗清單 | 看房與簽約前必須確認的關鍵項目（可互動勾選） |
| ⑪ 主觀感受對照附錄 | 純本地直覺喜好與家庭隨筆，供列印討論參考 |

### 即時公開網路查核

- 自動模糊化地址（移除門牌號碼保護隱私）
- 透過 DuckDuckGo 即時檢索學校額滿公告、公車/捷運班距與轉乘資訊
- 查核結果自動注入 AI 分析上下文，用公開事實驗證仲介說法

### 主觀筆記（獨立於 AI 分析）

- 星級直覺評分、最終決策標記
- 最愛亮點 (Highlight Pros) 與最在意雷點 (Deal Breaker Cons)
- 四大面向的「現在感受」與「未來想像」軟性隨筆
- 家庭討論筆記
- **以上資料僅保存於瀏覽器 `localStorage`**
- 單物件分析時不會傳送至 AI
- 橫向比較時 AI 會讀取這些筆記以識別偏誤，但**不會依據主觀偏好調整客觀評分**

### PWA 離線支援

- Service Worker 快取核心靜態資源
- 安裝後可離線開啟介面、瀏覽已儲存的分析報告、繼續編輯筆記
- AI 分析功能仍需網路連線

## 支援的 AI 提供商

| Provider | 預設模型 | 認證方式 |
| :--- | :--- | :--- |
| **OpenAI** | `gpt-4o-mini` | Bearer Token (`sk-...`) |
| **Google Gemini** | `gemini-3.6-flash` | API Key (URL param) |
| **Anthropic Claude** | `claude-sonnet-4-6` | `x-api-key` header |
| **本地模型** (Ollama / LM Studio / OpenAI-Compatible) | `qwen2.5:14b` | 可選 Bearer Token |

所有 Provider 皆支援自訂 Base URL 與模型名稱。生產環境啟用 SSRF 白名單防護，僅允許存取已認證的外部端點。

## 快速開始

### 環境需求

- Node.js ≥ 18

### 本機開發

```sh
# 複製專案
git clone https://github.com/david1990725/HouseAnalyzer.git
cd HouseAnalyzer

# 啟動開發伺服器 (同時提供 PWA 靜態檔案與 API 端點)
npm run dev
```

瀏覽 `http://127.0.0.1:3000`。

### 使用 AI 分析

1. 點選「**家庭資料**」，填入家庭成員與通勤需求（或載入示範資料）
2. 點選「**我的物件**」→「**新增物件**」或「**匯入 MD**」，建立租屋物件
3. 點選「**AI 設定**」，選擇 Provider 並填入 API Key 與模型
4. 在「**我的物件**」中勾選 2–3 間物件，點選「**AI 橫向比較**」
5. 在「**分析結果**」中瀏覽完整十一大模組報告

> **提示**：首次使用可點選首頁的「載入示範資料並體驗」，一鍵載入三間範例物件與家庭背景，直接體驗完整流程。

## 隱私與安全設計

- **API Key 生命週期**：僅存於 `sessionStorage`，關閉分頁即清除。伺服器端不記錄、不儲存。
- **主觀資料流向**：`localStorage` 中的主觀筆記在單物件分析時不參與任何 API 請求。橫向比較時會傳送至 AI 用於偏誤識別，但伺服器不儲存、不記錄。
- **地址模糊化**：網路查核時自動移除門牌號碼與巷弄號，僅以行政區與主要路段搜尋。
- **SSRF 防護**：生產環境啟用白名單，阻擋雲端 Metadata 端點與未認證外部服務。
- **請求體限制**：Analyze API 限制 200KB、Compare API 限制 300KB，防止濫用。
- **安全日誌原則**：伺服器端錯誤日誌僅記錄 `error.message`，嚴禁記錄請求 body。

## 部署

本專案前端為純靜態檔案，後端 API 為標準 Node.js Serverless Function 格式（`api/*.js`），可直接部署至：

- **Vercel**：將 `api/` 目錄自動識別為 Serverless Functions
- **任何靜態託管**：搭配自訂 Node.js 後端提供 API 端點
